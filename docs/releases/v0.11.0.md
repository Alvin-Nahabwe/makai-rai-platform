### What a person will see

- **Each question names its four answers in its own words.** 66 of the 67 questions (the personal data gate has its own Yes, No and Not sure) carry a label for each answer. Question Q-PP-01 reads "Yes, we compared them", "Partly, some options so far", "No, not yet" and "No comparison applies here", where it read Done, Partly, Not yet and Not applicable. The stored answer is the same, and so is what it does: Partly and Not yet still open a finding.
  - The question page's answer cards, its decision card and the reading card, and the working report's open items, show the running question's words and labels, so an earlier answer reads in 5.2.0's words there and one screen never mixes two versions' words. Question history, the findings pages and the documents (data card, model card, mitigation plan) show the label of the content version each answer was saved under. The "Saved at ... as version n" line and the data export print no answer word, as before.
  - Progress, stage lists, findings counts and the vocabulary keep the shared words, so "Partly" means one thing in every count.
  - Each card says what it counts as ("Counts as Partly. Some of it is in place, but not all of it."), so the stored meaning stays on screen.
- **The box under the answer asks what that answer leaves open.** Each question has a prompt for each of its four answers, and the prompt changes when the person changes the answer. A typed draft is kept when it changes. The box stays optional, as in v0.10.0. Not yet and Not applicable still require the main reason. The prompt itself is never printed; what a person types prints as before.
  - Where the typed text prints into a document (a data card or model card field, or the mitigation plan's list of reasons a question does not apply), the prompt says so ("this prints in the data card and mitigation plan").
- **The 67 questions are rewritten in one voice:** second person to the team, active and present. The median words on a question screen go from 121 to 96. By stage: pre-processing 133 to 103.5, in-processing 117.5 to 94, post-processing 112 to 88 (`node scripts/content/question-words.mjs`, run on `data/content/5.1.0` and `data/content/5.2.0` on 25 November). - **The green check is fixed.** An answer card draws no mark until it is chosen, each card is one control (not a radio plus a mark), and "Saved" has its own shape, a page with a folded corner. - **A label that starts with a defined term reads as one run of text.** The rehearsal found "Partly  , some of it in place" and "No,  not yet" with a gap beside the defined word. It is fixed in 68c5907a (see "Not verified": this fix was not rehearsed).

## Rollback

**The rule: fix forward with a later v0.11.x.** Follow 9.7 (and 9.1, 9.2 and 9.4 for the steps). An application rollback to v0.10.1 is an emergency stop only.

- After the migrator has run, v0.10.1 refuses saving, withdrawing and sealing, whether or not anyone has saved under 5.2.0. Its running content, 5.1.0, is no longer published (`resolveRunningContentVersion`, `lib/data/framework.ts` at v0.10.1). That is read from the code; the rehearsal's refused save was made with 5.2.0 answers present. The design had said a rollback is safe before the first 5.2.0 answer. By the code that is not so for saving.
- It also fails on pages that read a sealed review, and on pages that read a 5.2.0 answer. The rehearsal found more of these than 9.6 lists for v0.6.0, and 9.7 lists them.
- The only way v0.10.1 saves again is a database restore to BACKUP (9.3, with 9.7's note). It discards every write since BACKUP. Do not restore without saying so in the session.
- The hourly synthetic journey will fail every hour while v0.10.1 serves (its save is refused). Pause it and its check, and write down that both are paused, as 9.7 says.
- 9.5a does not apply: 0.11.0 changes no legal text.
