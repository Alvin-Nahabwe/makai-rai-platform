### What a person will see

- **The working report.** Anyone who can read a project, Assessors and Viewers included, can open it at any time, with no seal: from the project page's main action, a new "Working report" entry in the project rail, and each stage's end screen (`/orgs/<slug>/projects/<id>/report`).
  - Page 1, "Where this project stands": open findings grouped by risk area, then "Already in place" and "Doesn't apply".
  - Then a draft data card, a draft model card, and one draft mitigation plan per stage that has answers.
  - It downloads as one PDF or as each part on its own, up to 10 downloads a minute per person (#108). Past that, a download opened from the page comes back to the report page with "You can download 10 reports or parts a minute. Wait a minute, then try again."
- **Every draft says it is a draft.** Each page and PDF footer reads "Draft · from answers as of <date, time, EAT>". A draft has no seal and no fingerprint and is never written to `issued_documents`; the issue path refuses a draft at run time. Issued documents are unchanged and still need a sealed stage.
- **The end-of-stage screen,** shown after the last question of a stage is saved, and reachable again from the stage page and the stage's last question. Its main action opens the working report; it also offers the next stage.
  - An Assessor gets "Ask a reviewer to seal this stage", which opens the stage review and then reads "Review opened · waiting for an Owner, Admin or Reviewer to seal". The request notifies no one (D-413).
  - An Owner or an Admin gets "Open and seal this stage" while the stage has no review, and "Seal this stage" once one is open.
  - A Reviewer gets "Seal this stage" once a review is open.
  - A Viewer sees the status line while a review is open.
- **Per-stage progress on the project page:** "N of M" with a bar, the mix of statuses in words, and "Next: Question N · Continue" ("View" for a role that cannot record). M leaves out questions the gate removed.
- **A "what you get" line** at the top of the project page, and on Home for someone with no project yet.
- **The draft controls sentence.** Until content 5.2.0 is approved, page 1 and the draft mitigation plan list no control suggestions and read: "Suggested controls are on each question's page. They are listed here once experts approve the new risk-area mapping, and the list may change then."
- **The decision card.** The status cards, Reason and Decided by no longer vanish after the page loads in Chrome 158 (the cause of the "Done radio" CI flakes: `.decision-fields` was a size container, and Chrome sometimes left its children without layout boxes). The Decided by and Decided on row now sits side by side when the card's fields are at least 42rem wide and stacks below that, at any browser default font size.
- **Arriving at a question.** On a fresh load of a question page its heading takes focus without scrolling the page, so someone who scrolled while it loaded stays where they are. After Next, Previous, a link, a reload or back/forward, the heading is scrolled into view as before.
- **Notebooks.** The notebook requirements file that the platform serves pins tornado 6.6.1 and soupsieve 4.1.3; every other pin and every platform marker is unchanged.
- **Workshop load.** Working-report PDFs render in a worker thread, up to two at a time (one on a two-core host). Measured on a production build on the build machine with 21 simultaneous whole-report downloads: 0 errors (7 to 8 of 21 failed before), page median 78 ms (3,927 ms before), PDF median 2.5 to 3.2 s.

## Security

- **Dependabot:** 0 open alerts on main after #104 and #107 (checked 22 November, 14:33 EAT). #104 closed 48 (minimatch, medium) and 53 (effect, high), both development dependencies. #107 closed 49 to 52 (soupsieve, high; tornado, low). Those two packages are pinned in the notebook requirements file the platform serves; they are not installed in the app image.
- **Drafts cannot pass as issued records:** no seal, no fingerprint, never stored, refused by the issue path at run time (#98, reviewed on Opus with the ADR 0023 attack).
- **The PDF worker** sends back only frames matching a strict pattern, never a raw stack or message head, and the worker's text is never logged (#98, Task 16).
- **Secret scan:** gitleaks 8.30.1 over `v0.8.0..` the release branch head, network off: 82 commits (everything in this release, #108 and the release commit included), no leaks (22 November).
- **Security review of `v0.8.0..b5580f2b` as one change** (Opus, 22 November): 0 Critical, 0 High, 1 Medium, 3 Low, 2 Info. #108 is outside that range; it is the M1 fix and had its own reviews (Opus, approve with nits, all three fixed; Sonnet re-review, approve).
  - **M1 (Medium), limited before this release by #108.** Any signed-in member of any organisation could make working-report downloads answer 503 for every organisation by requesting made-up project ids: each id had its own rate-limit bucket. Now one person gets 10 downloads a minute, whatever the project (the owner's choice: "Small fix first (Recommended)"). What stays: a made-up id still takes a render permit before its 404, and the queue (2 running, 40 waiting) is shared by every organisation, so several accounts at 10 a minute each can still fill it. Register D-424.
  - **L1 and L2 (Low) stay**, in D-424: the report page and the end screen run their heavy read without the queue, and a render that has started is not stopped when its requester leaves.
  - **L3 (Low):** role-matrix O-13 no longer counts links inside Home's data lists, by the owner's choice of 20 November ("Ignore links, keep buttons").
  - **I1 (Info), a deploy dependency:** page 1 builds notebook links with `publicOrigin()`, which fails without `AUTH_URL` or `NEXTAUTH_URL`; a report whose page 1 shows a control with a notebook would then answer 500. Page 1 shows no controls until content 5.2.0 is approved, and 8.2 below checks that the host's `.env` sets `NEXTAUTH_URL`, the one the compose file passes to the app.
  - **I2 (Info):** notebook links are built with `new URL(file, publicOrigin())`, so an absolute URL in a content file would replace the origin. Content is platform-authored, so this is not exploitable today.
  - The review found no path across organisations, and drafts never reach the issue path.
  - **What the review did not do:** it read code only; it ran no app, no tests and no `npm audit`, and did not look up advisories for next 16.4.6, resend 6.39.0, effect 3.22.5 or typescript-eslint 8.73.
- The image scan runs after the tag (8.1).
