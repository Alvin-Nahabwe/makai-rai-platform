## What is released

v0.6.2 is v0.6.1 with the pinned nginx image moved. The version in `package.json` is `0.6.2`.

v0.6.1 was tagged on 12 November 2026 and was not deployed. The image scan run after its tag failed on the pinned nginx image: it holds `brotli-libs` 1.2.0-r1, which has a CRITICAL advisory (CVE-2026-111497), fixed in 1.2.1-r0 (register D-339). So v0.6.2 is the first release since v0.6.0 to reach the host, and everything `docs/releases/v0.6.1.md` lists as released arrives with it: version 2 of the legal texts, content 5.1.0, the two migrations and the rest. Read those notes with these.

What v0.6.2 changes on top of v0.6.1:

- The production compose file pins `nginx:1.31-alpine` at the digest beginning `sha256:713fc2eb`. It is nginx 1.31.8, as in v0.6.1's pin, and it holds `brotli-libs` 1.2.1-r0.
- The nginx test script (`scripts/nginx-test/up.sh`) and CI take the same pin. They pinned v0.6.0's nginx image, so since the compose file moved to v0.6.1's pin on 5 November the nginx specs had not run the image the compose file pins (register D-338). A unit case now reads the compose file's pin and fails unless the script and CI name that image and no other.
- The deployment runbook says what v0.6.2 is, that v0.6.1 is never a deploy or rollback target, and what a failed image scan means: it stops the deploy until the owner has read the finding and decided (8.1, 9.1, 9.6).

No file of the application changes: `git diff --name-only v0.6.1 4c4c2c30` lists nothing under `app/`, `components/`, `lib/`, `prisma/`, `data/`, `public/` or `ops/`. No key is added, removed or renamed in this release, and there is no migration beyond v0.6.1's two.
