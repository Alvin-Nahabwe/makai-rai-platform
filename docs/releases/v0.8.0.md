## What is released

v0.8.0 is stage 1 of the redesign built to the Route sketches. It follows v0.7.0 (tag `v0.7.0`, merge commit c1c933b6 of PR #95), which is the release the host runs now. The version in `package.json` at c4e0367e is still `0.7.0`; the owner ruled the next version number as 0.8.0 on 15 November 2026 (20:55 EAT), so the file has to change before the tag (to be confirmed).

The target is the owner's answers to ten open points, R1 to R11, given on 15 November 2026 between 09:10 and 09:13 EAT (`route-target-decisions.md`). Where that file and the spec, a plan or a sketch disagree, that file wins. Seven lanes built it on 15 November: the question page's frame and route column (lane 1), the decision card (lane 2), the rail, top bar, footer, Home and Projects (lane 3), the project page (lane 4), the sign-in and door pages (lane 5), the wording work (lane 6), and the fixes, the error pages and the design tokens (lane 7). A last lane (lane 8) was still fixing the final design review's findings when this draft was written.

Nothing stored changes in what the lane closes describe: the lanes name no migration, no stored decision, finding, seal or issued document that changes. Whether the whole release changes anything stored is to be confirmed by a diff against `v0.7.0` (`prisma`, `docker`, `package.json`, `package-lock.json`, `.env.example`), which was not run for this draft.

### What a person will see, screen by screen

- **The rail and the top bar (all signed-in pages).** The MAK-AI white logo with "MAK-AI RAI Platform" under it, linking to Home. Then the organisation line, Home, Projects, Findings, Guidance and Help. On every page under a project there is a project block: the project's name and its three stages, each linking to that stage's All questions page, each with one line of state ("You are here · N questions", "Not started", or "N questions · M no decision yet"). The foot of the rail holds the person and role, My account, Sign out and the theme switch, and stays in view while the upper part scrolls. "Organisation details" is now "Organisation". On a phone the top bar shows Menu and the logo; on project pages it shows the project's name, and on a page with a stage in the address also the stage and "All questions". A person held at a gate sees no project block. If Sign out is refused, "You are still signed in" shows and a second press is ignored while the first is pending.
- **The footer.** A navy strip in both themes with the MAK-AI and DSWB logos, the GIZ credit unchanged and four links. "Help and contact" goes to the contact part of Help. On signed-in pages it ends the content column beside the rail; on public pages it sits at the foot of short pages.
- **The theme.** Done is the one mark in green, a filled check (R8, below). In the dark theme the check is dark on a light green disc. The rail's "You are here" line reads in a peach accent in both themes, from a new colour token. The secondary button's label and border use the heading colour, which reads at 14.55:1 on the button's surface in the dark theme.
- **Home.** "Welcome back, {name}." A next-step card with "Start recording" before a first save and "Continue recording" after, beside "Choose another question". "Assigned to you" shows for any role with assigned items, then "Since your last saved change". The project's three stages sit as plates, each with its definition, open items first, then the tally with marks and a "Next:" line. An Owner or an Admin gets compact "Overdue mitigations" and "Findings with no mitigation yet" lists above the stages. A Reviewer gets three lists (reviews not sealed, sealed with changes since, findings raised) and no stage plates. A Viewer gets what was recorded in the last 14 days and what is still open. A first visit gets one sentence and "Create a project", or "Ask an Owner, Admin or Assessor…". There is no card of zero counts and no score.
- **Projects.** One list: active projects first, then archived, newest first. Each row is a plate with the name and one line of state, followed by "Showing 50 of N projects." The order is fixed. Unarchive is offered to Owners and Admins; other roles read "Owners and Admins can unarchive a project."
- **The project page.** Three stages, each a vertical line of stops, side by side from a 1280 px window and stacked on a phone. The head of the stage line the person last saved in carries the next question and the one primary button, "Continue recording" ("Start recording" before a first save). Each stage then shows "Still open in this stage", "Recorded so far", "Reviews", and a last stop with "All questions in this stage". The foot row "This project" holds Findings, Download records, Edit project details and, last, Archive project. Two changes the owner ruled on this page are listed under "Owner rulings and departures" and are decided, not yet built in this build (c4e0367e): the count in place of named questions (19:25; this build still names the first three questions and "and {k} more") and, at 20:50, no row of marks (the stage's tally is in words, each beside its mark) and mitigations shown as overdue plates plus one line "{n} other open mitigations" (this build still draws the row of marks). Whether lane 8's last commits carry either is to be confirmed.
- **A stage (All questions).** The route at page width: breadcrumb, the stage's meaning, the topics, the tally in words with small (i) buttons that open a definition, the seal banner and the filter chips, and every question on one line.
- **The question page and the recording workspace.** For someone who records, one white card, "Your decision", beside the question:
  - The saved mark and "Saved as version N · {date}" sit in the card's corner. The current answer is filled in and the card stays open after a save.
  - Status is a 2-by-2 grid of short cards. The sentence for the focused or chosen card shows under the grid.
  - Reason carries the question's own signed-off prompt. "Decided by" starts empty on a first decision. "Decided on" is three boxes with quiet shortcuts. On a re-decision it stays empty, with "Last decided on {date}" beside it.
  - Evidence sits on one line, "Evidence None yet", with Add a file and Add a link. Links show their host and say "opens another site" unless the host is the platform's own. An upload shows a progress bar. A refused upload says "Not uploaded: {name} was not accepted. Check the file, then add it again."
  - A sentence before Save says what this save will do, ending "This save becomes version N+1." when the answer differs from the saved version.
  - "Save decision" is the only orange control, beside "Next: {question words}" and "Question n of N". Save and Retry are one control whose label reads "Retry" only when the unchanged answer's request failed.
  - On a wide window the Save row pins to the foot of the screen while it would otherwise be below it. On a phone the fixed Save bar stays, and Next is a quiet link.
  - From 1160 px the route column sits to the left: the stage's name and meaning, a small "Show" filter, one navy line with a mark per question, far runs folded ("Questions 7 to 24"), "You are here" as an enlarged ring, and the next question marked "Next question". From 1440 px the guidance is a third column. A top strip shows the stage's tally (marks and words, with (i) buttons), then open findings and overdue mitigations. The question is the heading, one size smaller than the sketch so "Save decision" stays in the first view at 1280 by 800.
  - Guidance reads "What good looks like", then "Why this is asked" with the risk areas as linked labels, then "Ways teams address this (n)" folded by default.
  - A Reviewer, a Viewer and every role in an archived project get a reading card, "What the team decided", then "Still open on this question". A Reviewer can also raise a finding.
- **Findings.** Findings pages were reworded in this release, with the vocabulary's definition beside the first use of each term. A finding is closed by its decision only when no mitigation is open (see Security).
- **Documents and reviews.** Documents issued from now on name a finding by its question's words ("Finding on the question: {words} ({code})") and a risk area by its name then its code. A seal that does not match the record on Preview or Issue says so and offers no Retry. Documents already issued keep their stored words. The review page's facts and the seal step's counts are lists and tables. The reading-view note reads "You can read this record. Owners, Admins and Assessors can change it." (a Reviewer: "You can read this record and raise a finding. Owners, Admins and Assessors can change it.").
- **Help.** Help no longer lists a data-protection contact. Its glossary has one look for every entry, and storage consent is "consent to storage abroad" everywhere.
- **Guidance and About.** Definitions now stand beside the first use of a word on the framework and controls pages and on About. About's closing line "Sealing fixes the record so it cannot change." is removed because the seal is the fixed copy.
- **Sign-in and the door pages.** Sign-in, Forgot password and Set a new password sit in a gate frame: a navy column with the logo and the steps on a wide screen, a navy strip on a phone. The accept-the-terms page, the organisation chooser, the forced password change and the invitation page use the same frame. A person who is asked to accept changed legal texts sees "The terms have changed", each text's old and new version, and "What changed" in the owner-approved summary. The invitation page's route is its stepper (Your details, Accept the terms, Join).
- **Session and sign-out.** The warning states the true rule: "For your security, you are signed out 12 hours after you sign in, or after you last chose Stay signed in. Choose Stay signed in, then save your work." When the time passes, a notice gives the real reason and a "Sign in again" button. After sign-in on a browser holding another account's unsaved text, a card asks what to do ("Sign out and leave it" first). If next-auth does not confirm that a sign-out ended the session, the page says "You are still signed in" and a second press retries.
- **My account.** Reworded in lane 6 (definitions at first use). The close does not name other changes.
- **Errors and not-found.** A page that does not exist shows a "Page not found" card in the gate frame's look, with "Go to your home page" or "Sign in", and echoes no path or name. Inside the signed-in shell it shows the same card in the shell. The error page and the last-resort page keep the v0.7.0 look (see "Owner rulings and departures", probe D).
- **Messages and emails.** Refusals from the platform's requests are in plain words (for example, "Too many attempts. Wait 1 minute, then try again."). The reminder email says "7 days overdue". The default administrator name is "MAK-AI administrator". The "account created" email gains a sign-in link.

## Security

- **L-1 (Low, from the 0.7.0 security review).** The Guidance pages (framework and controls) could be reached by client-side navigation past a sign-in gate or a dead session. Fixed (lane 7, 0975d270, with a browser spec e7ef78e0 and a fix b62eae6b): both pages now await `requireIdentity()` and a lint (`__tests__/lint/layout-gate-siblings.test.ts`) stops a page from leaning on a gating layout that holds another page. The close notes that the first reading overstated the gap: the layout already gated a navigation into `/explore`, and the hole was between Framework and Controls.
- **R11 and L-2 (Low).** Route 11 (close by decision) used to accept a close while a mitigation was Planned or In progress. It now answers 409 `finding_has_open_work`, with the close box's own sentence, and writes nothing (lane 7, 7d533c60, review fix a69a4848). A stale page that presses "Close finding" sees that sentence under the button. Two protected-test replacements were recorded in `__tests__/lint/test-replacements.json`. The page does not refresh after the 409.
- **Sign-out (lane 5).** If next-auth does not confirm the session ended, the page stays and says so, and no path navigates to sign-in while the session lives. This also fixed a cross-site request forgery token that could not be fetched and left drafts cleared and the session live (L5-11).
- **Link display (lane 1).** One parse (`webLink`) decides how an evidence link is shown, so `https:evil.example` reads as an off-site address and not as a same-origin path. The same helper serves the writer's evidence list.
- **Error and not-found pages (lane 7).** They echo no path, slug, name, message or stack, and answer a member and a non-member the same. The code review and the security review each found the property to hold, and a mutation that echoed the path broke two tests.
- **Reviews.** The closes of lanes 1, 5 and 7 record a security review; the other lanes' closes were not traced for one (to be confirmed). No independent review read the whole of `v0.7.0..` as one change. That review is to be confirmed.
- **Secret scan, repository and image.** To be confirmed. The coordinator's ledger records a gitleaks run (v8.30.1, 292 commits, no leaks) and an image scan of v0.7.0 (success), both before this release's changes.
