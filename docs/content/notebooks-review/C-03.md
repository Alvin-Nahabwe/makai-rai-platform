## Items

### 1a. Method in plain words, Step 2: change

- **Cell:** 8, "### Step 2: missing values, by column and by group"
- **Finding:** the prose says the systematic-missingness comparison runs "for each column with some missing values", but cell 9 runs it only on `with_holes = missing_by_column[missing_by_column >= 0.01]`. On the example data `diag_2` (0.4 in 100 missing) is never compared across groups. The explanation does not describe the method that runs.
- **Exact change:** replace `for each column with some missing values, it compares` with `for each column with at least one value in a hundred missing, it compares`.

### 1b. Method in plain words, Step 3: change

- **Cell:** 10, "### Step 3: duplicates, and the difference between a duplicate and a repeat visit"
- **Finding:** the prose says "Three counts", but cell 11 computes and shows a fourth, `rows identical apart from both identifiers (same details, could be different people)`, which no text explains; the table also shows two figures on repeat visits. The same edit makes the near-duplicate part of the 10.5.2 entry visible (item 4).
- **Exact change:** replace the "What this does" paragraph and its numbered list with:

  ```
  **What this does.** Four counts, then how many people appear more than once and the most rows held by one person.

  1. **Exact duplicates**: rows identical in every column.
  2. **Near duplicates, apart from the row identifier**: rows identical in everything except the column that is unique to each row. These are copies that got a new number.
  3. **Near duplicates, apart from both identifiers**: rows identical in everything except the row identifier and the person identifier. These may be one person entered under two numbers, or two people whose recorded details happen to match; only looking at the rows can tell which.
  4. **Repeat visits**: rows that belong to a person who already appears in an earlier row.
  ```

  and in "What it does not show", replace `or rows for the same person under two identifiers.` with `or rows for the same person under two identifiers whose details also differ.`

### 1c. Method in plain words, Step 5: change

- **Cell:** 14, "### Step 5: outliers are flagged, never deleted"
- **Finding:** "For counts where most values are zero, the rule flags every non-zero value" is not what the IQR rule does. It flags every non-zero value only when more than three values in four are zero (both quartiles 0). The notebook's own column `number_inpatient` is mostly zero (66.5 in 100) and the rule flags only values of 3 and above (upper fence 2.5, executed output).
- **Exact change:** replace `For counts where most values are zero, the rule flags every non-zero value, which is a sign the rule does not suit the column.` with `For counts where more than three values in four are zero, both quartiles are zero, so the rule flags every non-zero value, which is a sign the rule does not suit the column.`
