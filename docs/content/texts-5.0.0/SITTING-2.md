## How the batch hash is computed

For a stage, the payload is `{ "batch": "<stage>", "questions": [ { "id", "text", "expectedPractice", "whyAsked", "reasonPrompt", "evidenceExamples", "helpText", "example" }, ... ] }` in the order teams see the questions, with `null` for a missing help text or example. For the fourth batch it is `{ "batch": "help-and-reason-codes", "documentHelp": { data_card, model_card, mitigation_plan }, "reasonCodes": [ { code, status, label, useWhen, reasonMustSay }, ... ] }`. The hash is the lowercase hex SHA-256 of the UTF-8 bytes of the payload's canonical JSON: `signOffHash(signOffPayload(content, batch))` of `lib/content/signoffs.ts`. The committed hashes were computed with `render-tables.ts texts` and with `signOffHash` directly, and agree. The alternative hashes apply exactly the wordings shown in T1, T2 and T4 to the same payloads.
